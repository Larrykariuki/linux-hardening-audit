# WSDD process investigation on Kali linux operating system
 

**Investigation date:** 7 November 2026
**System:** Kali linux
**Status:** CLOSED

## 1. My Objective
The purpose of the investigation was to determine whether a running 'wsdd' process on my Kali linux system
was legitimate or could pose a threat to my system. The investigation began when I ran'ss -tulnp' to inspect every port on my machine
that was open and waiting for connections and what program owns each of them. During the inspection, I 
noticed processes including wsdd and ollama which prompted me to investigate their purpose and understand why 
they were running but on this investigation I focused primarily on WSDD
I investigated its parent process, the location of the executable, network activity, installed packages and the 
system logs

## 2. Process Identification

The command for the process was:
'python3 /usr/bin/wsdd'
The process was launched through the GVfs desktop file-management services as shown below using the process tree

'''text
systemd
|
|____systemd --user
     |
     |_____gvfsd
           |
           |_______gvfsd-wsdd
                   |
                   |____python3 /usr/bin/wsdd
'''
## 3. Package Verification

I checked which installed packages owned the relevant files and the commands that I used were

'''bash 
dpkg -S /usr/bin/wsdd
dpkg -S /usr/libexec/gvfsd-wsdd
dpkg -l|grep -E 'gvfs-backends|wsdd'
sudo dpkg -V wsdd gvfs-backends
'''
Both the wsdd and gvfs-backends were installed packages,
and the package verification produced no output indicating that no package verification differences were detected

## 4. Network Investigation
WSDD supports web service dynamic discovery (WS-Discovery) which is a package or a small background service(daemon) 
that allows linux operating system to be discoverable by  windows computers or enables compatible devices and services to discover one another in a local area network through ws-discovery
The investigation examined UDP port 3702 and multicast networking to understand how wsdd communicates with the other
devices on the network

Commands used are:

'''bash
ss -uapn
ip link show wlan0
ip -o addr show dev wlan0
ip -6 maddr show dev wlan0
ip -6 route show
'''
The WSDDs network discovery activity was consistent with the purpose that was intended for

## 5. Log Investigation
I examined the system journal to understand the errors that were generated by the wsdd during its operation and
The journal contained several errors which include

- **Errno 101 - Network unreachable:** whereby the wsdd attempted network communication when the network was unreachable
- **Errno 99 - Cannot assign requested address:** whereby the wsdd attempted to bind a socket to an address that could not be assigned at that momment
- **Errno 9 - Bad file descriptor:** this is where the wsdd attempted to use a socket or file descriptor that was no longer valid

The IPV6 traceback showed WSDD attempting to bind a UDP socket while processing a network address change. 
The available evidence suggests a possible network interface or address transition issue, I failed to establish the exact triggering event
also seperate GVfs PTP errors were observed but were not identified as WSDD errors

## 6. My Findings
Based on my investigation I have established the following:
1. WSDD was owned by an installed Debian package 
2. Its executable passed package verification
3. Its parent process was associated with GVfs
4. Its network activity was consistent with ws-Discovery
5. The observed errors were not sufficient enough to establish malicious activity
6. Then the wsdd was not running during a later process check
The findings have helped me to distinguish between normal system activity and  behaviour that requires further investigations

## 7. My Conclusion
The Investigation result did not identify any indicators of comprise that was associated with WSDD within the scope of investigation
The process was linked to legitimate packages and its parent process was associated with GVfs
The IPv6 socket initialization failure remains unexplained at that exact triggering-event level.
I therefore closed the investigation without disabling wsdd or making any unecessary changes to the system
This conclusion does not mean that my system is free from malware or other security issues
